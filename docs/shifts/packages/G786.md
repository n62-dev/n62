### gorge, G786: median and the quartiles of a float list are never 0 at a working precision above 14 digits, branch `p1/gorge-floatsort`
**Lane:** B, night-safe, Opus (a Giac patch; a wrong number). **The owner's yes:** 2026-11-22 (G398f1: the finding of G398's fix round 2 gets its own package). **Starts when:** G398 merged (G398f1). A fix.
**Why:** Giac's `ascsort` (stock giac 2.1.0 `permu.cc`, under `median`, `quartile1`, `quartile3`, `quantile`, `quartiles`) puts 0 for each element whose `evalf` is not a `_DOUBLE_`; above 14 digits a float element is MPFR. Probe (coord, 2026-11-22, phase-1 engine `_out/gsl`, `engine/giac/smoke.mjs`): at `Digits:=20`, `median(evalf([1,2,3,4]))` = 0.0, `median(evalf([3,1,2]))` = 0.0 (right 2), `quartile1(evalf([1,2,3,4,5,6]))` = 0.0 (Giac's own convention at Digits 12: 2), `quantile(evalf(…),0.5)` = 0.0; a list of doubles stored at 12 digits is right at 20 (`[0.5,1.5,4.0,1.5]` for `[1.5,-2,7,3.25,0.5,4]`). G398's fix round 2 saw it in Home: `quartile1(Lq398)` after `Lq398:=approx([1,2,3,4,5,6])` shows ⚠ 0 (38 digits), and Home's float path after the exact path's time-out reaches it (golden `steps` g42-quartile1-six showed 0 on the 8× clock, runs 1377 and 1472).
**Not this package:** which median and quartile convention is right (Giac's median of an even list takes the lower middle; g2.yaml question 67, no code depends on it). Expected values here are Giac's own at Digits 12.
