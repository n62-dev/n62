### gorge, G272: the uncertainty budget's model (UI-free), branch `p1/gorge-budgetmodel`
**Lane:** night, Opus (every display rule of the budget is decided here). **Starts when:** G270 and G271 merged, and the owner's yes on mh-C decision 1 (rows over σ², with one signed second-order row).
**Why:** no phone calculator states each input's share of σ². The rules have edges that a naive percentage gets wrong (verification 2026-11-08): an exact zero row must not read "< 0.1 %"; `a = 0, b > 0` (`pasupm(0,0.1)^2`, σ 0.014 ⚠) would give inputs 0 % and second order 100 %; a small negative row would lose its sign; rows can exceed 100 % with no ⚠ (`sin(0 ± 0.2)`: σ 0.20, rows 104.2 % and −4.2 %).
The model has no cross terms: GUM eq. 10 holds for its inputs only. Correlation is modelled by shared leaves where a basis exists; R61 chips, basis-less constants (`app/src/engine/constBasis.ts:58`, `basisOf(e) ?? ""`) and CODATA leaf correlations are treated as independent. Effect by mpmath, L = 2, u = 0.01: M = L² chained into M·L gives 0.0894 where the truth is 0.12 (too low); M/L gives 0.0224 where the truth is 0.01 (too high). So a chip's row carries a note, and σ and shares can be off in either direction.
**Read:** (line numbers as of de659c02; recheck at start) `app/src/units/uncertainty.ts`; `app/src/units/evaluate.ts:87-89` (`pasuo`, the fallback); `tests/golden/oracle_constcorr.py` (the oracle's form); GUM 5.1.2-5.1.3, 5.2.1, 5.2.4.

**The rules.** Input: `terms` (`{key?, t, uy}`, G271), `second` (b; absent on Home, which is first order), `why` (`order2`, `singular`, `jump`, or none), `noBasis` (keys of constants with no basis, from the caller). a = Σt. Shares by BigInt on the decimal text, never `Number`.
1. σ 0 (`a = 0`, `b` 0 or absent): no budget. `why` = `jump` or `singular`: no shares, reason named (a derivative of 0 on a step function would mislead). `a = 0, b ≠ 0`: no shares, reason `firstOrderZero`.
2. Base D = a + b, when a + b > 0. Each row 100·tᵢ/D; one signed row "second order", 100·b/D, when b is given and nonzero. When a + b ≤ 0 (as `pasuo`, which then uses a): D = a, no second-order row, `fallback: true`.
3. Each share rounded on its own to 0.1 %, half away from zero, never adjusted to force 100. Exact 0 is `0`. Magnitude below 0.05: `< 0.1` when positive, `> −0.1` when negative.
4. `rounded: true` when the sum of the shown shares, each `< 0.1` or `> −0.1` counted as 0, differs from 100.0.
5. `over100: true` when a share reads above 100.0, so that the sheet adds its one line.
6. Rows sorted by share, largest first, input order on a tie; the second-order row last. Each row's `uy` at 2 significant digits (`uncertaintyText`). `independent: true` on a key starting `pasr_` and on a key in `noBasis`; a typed ± and a leaf have none.
