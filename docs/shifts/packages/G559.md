### gorge, G559: eigenvals of a float matrix are its eigenvalues, never the rows of a diagonal matrix, branch `p1/gorge-eigvalsfloat`
**Lane:** B, night-safe, Opus (a Giac patch; a wrong result shape, one case unmarked). **Starts when:** –. After the tag unless a lane has room before it (mostly shown under ⚠).
**Why:** (T2 bug hunt 2026-11-16, F312; `../drafts/2026-11-16-ultra/t2-bughunt/hunt-stats.md`, probes `probes/stats/`, engine `_out/gsl`, phase-1 `e93dec77`.)
- **What happens:** `E:=approx([[1,2],[3,4]])`, then `eigenvals(E)` shows `{[5.37228132327,0],[0,-0.372281323269]}` ⚠, a list of vectors. `max(eigenvals(E))` then returns a vector.
  - `eigenvals(approx([[0,-1],[1,0]]))` shows `{[i,0],[0,-i]}` with **no mark**.
  - A 3 × 3 gives three 3-vectors.
- **Right** (`source: oracle`, mpmath `eig`, 30 digits): {5.37228132327, −0.372281323269}; {i, −i}.
- **What works today:** exact input (`eigenvals([[1,2],[3,4.5]])`), a symmetric float matrix, and the double branch at Digits 12.
- **Cause (stock giac 2.1.0, as read by the hunt; recheck):** `vecteur.cc` about 15141-15145, `egv` for a numeric non-symmetric matrix whose entries are not doubles (MPFR, Digits ≥ 15). It ends with `schur_eigenvectors(p,d,…)`, which fills `d` with the diagonalised Schur matrix whatever `eigenvalues_only` says. `_eigenvals` returns `d`'s rows. The double branch (about 15103-15114) takes the diagonal.
- **Precision:** the values carry double precision only there (francis_schur with a double eps). Home's ⚠ on them is right and stays.
