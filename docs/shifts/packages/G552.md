### gorge, G552: an exact power past Home's pow limit is worked out as a float, never Giac's "Exponent overflow", branch `p1/gorge-powfloat`

**Why:** (T2 bug hunt 2026-11-16, F303; `../drafts/2026-11-16-ultra/t2-bughunt/hunt-roots.md`, probes `probes/roots/`, engine `_out/gsl`, phase-1 `e93dec77`.)
- **What happens:** Home `\left(1+\frac{1}{365}\right)^{36500}` shows `GIAC_ERROR: Exponent overflow Error: Bad Argument Value` (path `float-error`, no value, no mark). This is daily compounding over 100 years.
- **The same for:** `(1+1/100000)^100000` (the classic (1+1/n)^n → e), `(11/10)^100000`, `(101/100)^(5*10^4)`, `2^1000000`, `3^(10^6)`, `(1/2)^(10^6)`.
- **Right values** (`source: oracle`, mpmath 50 digits): 2.34457556594564E43; 2.71826823717449; 1.85573441754682E4139; 9.9006562292959E301029. All lie inside MPFR's range.
- **What already works:** the same values typed with a decimal answer: `1.1^100000` ≈ 1.85573441755E4139, `(1+1/100000.)^100000` ≈ 2.71826823717.
- **Cause:**
  - Home sets Giac's pow limit to `powLimit: 1e5` (`app/src/engine/homeDefaults.ts:17`; `host.ts:1313` `setPowLimit`; `engine/giac/wasm/api.cc:487`, the guard on |n·ln b| for an exact power).
  - The comment at `homeEval.ts:59-60` says such a power "goes to the float path", and it does: `homeEval.ts:655` `viaFloat("float-error")`.
  - But the float path (`numeric.ts:935` `floatPathFacts` → `:977` `pasf:=(<text>)` at Digits W) runs the same text with an exact base. Giac computes the exact power again and hits the same guard. `atDouble` (`homeEval.ts:621`) fails the same way.
  - Raw Giac: `evalf((1+1/365)^36500)` fails, while `evalf(1+1/365)^36500` = 0.234457556594563703047679098932e44.
- **Known neighbour:** backlog F217 (`2^(-1073741000)`, filed as extreme, no package). This package covers it when the fix reaches it; the report says whether it does.
