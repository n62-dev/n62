### annabell, A121: night.sh and usage limits: henri at a limit, a count that never resets, waits that spend steps, branch `p1/annabell-nightlimits`
**Lane:** by day and only while no lane runs (`ls .coord/night-*.pid` empty), Sonnet. **Starts when:** now.
**Why:** (owner, 2026-11-08) from 11-17 the plan is Max (5x), so the lanes will reach limits; no pipeline run has logged one yet. Five defects meet there.
- **A henri call at a limit is a bad reply.** `ask_henri` (`scripts/night.sh:151`) turns any failure into `(henri failed)`. In the main loop that counts as `bad`, so two in a row end the lane with `STOPPED ... henri gave no pipeline command twice`, a minute apart and with no wait. In closing step 1 (line 238) it reads as "no Opus pass line" and the last pass is lost, against the header's line 26.
- **`limits` never resets** (line 182). Seven limits across a whole run end the lane, even if each cleared after one wait. And six waits of 1800 s are 3 h, less than the CLI's five-hour window (18000 s).
- **The limit pattern misses the CLI's words.** `usage limit|rate limit|429|overloaded` (`scripts/pipeline.sh:285`, `:659`) does not match `You've hit your 5-hour limit`, `You've hit your weekly limit`, `You're out of usage credits` or `You're out of extra usage` (text read from Claude Code 2.1.319). A worker at such a limit ends as an ordinary NOT MERGED and the queue burns on.
- **The report has no limit check.** `scripts/pipeline.sh:424` ends in `|| true` and the next lines exit 0, so at a limit the CLI's message is logged as the report and night.sh writes SHIFT DONE. The rc 75 branch at `night.sh:250` can never fire.
- **A pipeline rc 75 spends a step.** `night.sh:275` falls through to the tick at `:281`, so waits eat the budget-sized `--max-steps` (rules 4a) and close the lane early.
