### gorge, G576: Home gives 2^1000000 a number, as it does 2^(1ᴇ6), branch `p1/gorge-bigintpow`
**Lane:** B, night-safe, Sonnet (the float path of one input shape; golden rows). **Starts when:** any time; the background stream (extreme inputs), after the tag.

**Why** (F352, found by T4 on 2026-11-16, not the owner; session S05 "never a quietly wrong number", "10^400, 1000!"): an integer power whose exact value is past Home's exact limit gets no number, while the same value typed with a float exponent does. Playwright (Pixel 7, real engine, phase-1 e93dec77) and `node tools/probes/engine.ts`:

| Input | Home now | Right (mpmath, 30 digits) |
|---|---|---|
| `2^(1ᴇ7)` | ≈ 9.04981730636E3010299 | 9.04981730636E3010299 |
| `2^(10^7)`, `2^10000000` | The calculation failed | 9.04981730636E3010299 |
| `2^1000000` | The calculation failed (probe: `GIAC_ERROR: Exponent overflow`) | 9.90065622930E301029 |
| `10^(10^6)` | The calculation failed | 1E1000000 |
| `e^1000000` (eˣ key) | ≈ 3.0332153968E434294 | 3.03321539680E434294 |

**Cause:** Home sets Giac's power limit to `powLimit` (`app/src/engine/homeEval.ts:59-62`, applied by `host.ts:1313`), so an exact integer power past it fails "at once" and goes to the float path (`homeEval.ts:655`, `viaFloat("float-error")`). The float path (`homeEval.ts:602`, `floatPathFacts`) evaluates the same text under the same limit, so it fails the same way. Raw Giac without the limit gives `evalf(2^1000000)` = 0.990065622930e301030 (smoke.mjs); with a float exponent at double precision it is `infinity`, so the float path needs the limit lifted (or the exponent at P digits), not a double.

**Read:** `app/src/engine/homeEval.ts:55-62`, `:600-625`, `:650-656`; `floatPathFacts` in `app/src/engine/numeric.ts`; `host.ts:1298-1330`; F217's line in backlog.md (`2^(-1073741000)`, the same message, the other sign) and G187's `powerPastRange` (`homeEval.ts:673`, MPFR's own range: past it, a refusal stays).
