**Why:** (the owner, 2026-11-16: letters get unit slots; sandra's plan, revised; sofia's review, findings 1, 10, 14, 19 and 20.)
- **Today:** a letter gets no slot (`app/src/input/unitFormula.ts:182`; `app/src/input/parse.ts:688` "a unit slot goes right after a number"). After R315 only a name stored with a unit gets one. So `m·c·T` cannot be checked or worked out with units.
- **Two rules today:** `slotFormula` scans the LaTeX with its own idea of a name, and that idea already differs from the parser's:
  - `x2` is one name to the scan (`:143-148`) but `x*2` to the parser (`tools/probes/parse.ts`).
  - `f(x)` is a call to the parser even when f is not stored, while `x(2+3)` is a product.
  - The scan cannot see bound variables (∫, ∑, d/dx) at all.
- **The fix:** the parser decides which names get a slot: one slot per name token (a letter, a letter with a subscript, a Greek letter, or \`\operatorname{…}\`, read through the name registry, G393, stored or free since R356); letters typed apart (\`\Delta T\`, \`ab\`) are a product, one slot each, drawn with R355's dot. \`slotFormula\` only puts the prompts where the parser says.

**Stored data:** number and `\res` slots keep `u1…uN` in written order, as today. Every name slot, R315's and this package's, takes the ids after them, `u(N+1)…`, in the order the names first appear. An old row keeps its units on the same numbers, and no stored value changes form, so there is no `DATA_VERSION` step. R292's fixture (`app/src/state/fixtures/backup-0.1.0.json`, its `A\cdot2` row) pins it.
