**Read:** `scripts/pipeline-lib.sh` (`preflight_lint`), `scripts/pipeline.sh` (the merges at the pass and the package, the `--no-merge` hint), `scripts/pipeline.test.sh`, `tools/README.md`.

2. **The change:**
   - **`tools/repo-weight.sh [--limit <bytes>] <tip> <base>...`** (default 1 MB): bases may be refs or `--remotes=<name>`, expanded with `git for-each-ref`; `set -o pipefail`; `{ printf '%s\n' "$tip"; printf '^%s\n' "${bases[@]}"; } | git pack-objects --revs --thin --stdout -q | wc -c`; a failed pack-objects exits 2. New blobs come from `git rev-list --objects <tip> --not <bases>`; each binary (a NUL in its first 8 kB) or over 1 MB raw whose path is outside the allow-list is printed. Exit 0 / 1 / 2.
   - **`tools/weight-allow.txt`:** one glob per line with a comment: `fastlane/metadata/**`, `logo/**`, `android/app/src/main/res/**`, `app/public/icons/**`, `tests/ui-walk/probe/**`, `tests/ui-walk/ui-map.json` (the last two: owner, 2026-11-16, T5).
   - **The pipeline:** the guard reads the allow-list and the package's Weight line from phase-1 (`git show phase-1:…`), never from the branch. It runs at the merge sites (pass and package) as a `queue_stop` with the WEIGHT line: a worker cannot shrink history with a new commit, so the owner decides (squash the branch onto phase-1, or the Weight line). The `--no-merge` hint prints the weight too.
3. **Docs (the same diff):** `tools/README.md` (the command, the allow-list, the override); docs/shifts/rules.md section 4 one line (a branch over 1 MB or with a new binary needs the owner's Weight line; a hand merge runs `tools/repo-weight.sh` first).
