### ron, R251: the RPN operation composer and its binding to a row, UI-free, branch `p1/ron-rpncompose`
**Lane:** A, day, Opus. **Starts when:** R250 is merged (the owner's yes on mh-D1, 2026-11-15: before the freeze).
**Why:** (mh-D1) a stack operation must be one ordinary row: LaTeX built from `\res` chips and handed to `Session.submit` (`app/src/state/session.svelte.ts:463`), or, when an operand carries a unit, to the unit view's evaluation of that line. Then there is one evaluation path, and Cancel, the marks, σ and the audit come free. Exact stays exact because the chip's value is what the row reads. Operands leave the stack only when the row is **done**: an error (`Units don't match` included), a Cancel or a refused `submit` (it answers `undefined` when `busy`) leaves the stack as it was.
- **Units and ± (mh-D3, the owner, 2026-11-15):** Home has no units (`app/src/input/chips.ts:9`, P8), so an operation with an operand whose chip has `unit` goes through the port's `submitUnits`: the same line in the unit view, where the slot after each chip starts with its unit and a σ chip is `pasupm(value,σ,key)`, one input per chip (docs/04 4.3; R115). Without a unit it goes through `submit`; Home carries a chip's σ (R61, G355). Before either, two operands with different uids that share an input (R250's `sharesInput`) are refused: no row, answer `"shared"`. The new level's `inputs` is the union of the operands'.

**Arity (R250's `arityOf`; this package supplies the forms):**

| Arity | Key, layer | LaTeX, with A = level 2 and B = level 1 |
|---|---|---|
| 2 | `add`, `sub`, `mul` primary | `A+B`, `A-B`, `A\times B` |
| 2 | `div`, `pow` primary | `\frac{A}{B}`, `A^{B}` |
| 1 | `sq` primary, `div` shift | the key's template with `#@` = B: `B^{2}`, `B^{-1}` |
| 1 | `sq` shift, `sin` `cos` `tan` `ln` `log` primary and shift, `neg` shift, `enter` shift | the key's template with `#0` = B |
| 0 | `emark`, `paren`, `d8` shift, `frac`, `pow` shift, the palettes, every other key | none: never reaches the composer |

A and B are `\res{k}{shown}` (`resChip`, as `app/src/entry/controller.ts:220` inserts it): compose numbers the distinct identities (uid and chip, R250) of its operands `res:1`, `res:2` in level order; the same identity gives the same key. The templates are read from the key's action, never copied, and the one-line (`line:`) forms are never used here. The power takes the whole chip (parser golden `chip-res-04`), so a negative base needs no bracket.
