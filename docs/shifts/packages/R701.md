### annabell, R701: the folder plugin is never handed to a Promise (Sync folder works on Android), branch `p1/annabell-folderproxy`
**Lane:** B, Sonnet; the night's device (the test build). **The owner's answer (2026-11-16, T5):** in the fix lane before the v0.1.0 tag (release-0.1.0.md, the freeze row). **Starts when:** –. It is a fix (F380) of a shipped feature (R128), so it runs before the v0.1.0 tag, in the test nights.

**Why:**
- **F380 (T5, [findings.md](../../research/t5-ui/findings.md)):** on the APK, Settings › Data › Sync folder › Choose folder opens nothing. The console gets `Error: "N62Files.then()" is not implemented on android` twice. The same two errors come on a start and when the app is left.
- **The cause:** `app/src/clipboard/folder.ts:53-61`.
  - `async function plugin()` returns the `registerPlugin` proxy. Resolving the Promise with it calls the proxy's `then(resolve, reject)`.
  - The proxy turns `then` into a native call. That call rejects unhandled with UNIMPLEMENTED (the console line), and it never calls `resolve` or `reject`.
  - So every `await plugin()` stays pending for good: `pickFolder`, `folderName`, `folderWrite`, `folderAppend`, `folderTail`, `appendChecked`, `folderModel`, `folderRead` and `folderList`.
- **Why no test saw it:** `app/test-device/folder.rec.ts:103` calls `Capacitor.nativePromise` around `folder.ts`. In a browser `plugin()` returns `undefined` first.
- **Nothing else is like it:** `files.ts:64` calls `.save` on the proxy directly. Any other `return registerPlugin(` from an `async` function must be checked: `grep -rn "registerPlugin" app/src`.

   - It is kept in a module variable and handed back wrapped (`{ plugin }`) or read from that variable, never as a Promise's value.
   - A comment at the place names the trap: a Capacitor proxy is thenable.
