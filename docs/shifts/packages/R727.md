### ron, R727: Shift + Select copies the entry line's selection when there is one, before the picked or last row, branch `p1/ron-copyselection`
**Lane:** the freeze's fix lane, Sonnet (owner, 2026-11-17). **The owner's yes:** 2026-11-17 for Copy on Shift + Select (R723); this package settles what it copies (the owner's yes, R727 before the tag; the drafts folder's 2026-11-17-keys/ANSWER.md, point 2, outside the repo). It must land before the tag, because it changes what a press does. **Starts when:** after R723, which adds `special copy`. Must merge by Mon 11-23.

**Why:**
- **The pair reads "select, then copy".** Select grows the line's selection (R279), and Shift + Select sits on the same key. R723 has it copy the picked row, else the last row (R723, "The result"), so the selection the user just made is ignored. That is a wrong copy the user cannot see until they paste.
- **The text already exists.** A hold on a history row's input copies its plain text: `entryText(latex)` (`clipboard/actions.svelte.ts:148-154`, `clipboard/plaintext.ts:189`). The selection is copied the same way.
- **Copy must not end the chain.** Any key other than Select and Deselect ends the Select chain (`keyboard/route.ts:520`, `entry/grow.ts:168-171`). After Select, Select, Copy, Deselect must still walk back one step.

**The result:**
- **Shift + Select (and its flick up, its desktop key Alt+Shift+Y)** copies the first match:
  1. the entry line's selection, when it is not collapsed (from Select, a drag or a double tap in the line), as `entryText` of its LaTeX. The selection and the Select chain stay. Copy is counted as a hold's copy is (`ops.acted("copy")`);
  2. else R723's rule: the picked row's full value, else the last finished row;
  3. else a dead press.
- This holds on any entry line that shows: Home, CAS, and an app's line. With nothing selected in an app, it stays a dead press, as R723 says.
- The notice is the usual "Copied" (`clip.copied`).
- Ctrl+C inside the field stays MathLive's own copy (`entry/hwkeys.ts:30`).
