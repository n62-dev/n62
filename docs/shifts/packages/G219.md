### gorge, G219: the sync queue: at-least-once, in order, coalesced, branch `p1/gorge-syncqueue`
**Lane:** night, Opus (lost or duplicated lines). **Starts when:** A101 and G218 merged.
**Why:** A line is confirmed only when `appendChecked` says so; until then it stays queued, across a crash or a day with no folder. Bursts of results must not mean one write per result: the plan's "coalesced" was not designed, so here is the rule. The file is what the laptop reads, so a line dropped at the cap must leave a mark in the file, not only in a status on a Settings page.
**Read:** `app/src/state/storage.ts` (the `idbKv` pattern, `units/userCells.svelte.ts:13-15`); `app/src/state/backup.ts:17-45` (`BACKUP_KEYS`, `LEFT_OUT`); `app/src/clipboard/folder.ts`; `app/src/sync/files.ts`; `app/src/main.ts:62-67` (the hide flush).
1. **Tests first, failing on phase-1** (`app/src/sync/queue.test.ts`, port and kv stubbed, fake timers):
   - lines are written in order; a failed write leaves them and retries on the next add or flush, in order;
   - "cantAppend" and "unavailable" keep the queue and set the status (`ok`, `queued n`, `can't append`, `unavailable`);
   - coalescing: a burst within 2 s is one append per file, text joined in order; a hide (`flush()`) writes at once;
   - a crash after the append and before the dequeue writes the line again next start: same `id`, and the reader's rule (G210) takes it;
   - the queue persists: a second instance reads it; over its cap (the worker names it from `HISTORY_LIMIT`, in the report) the oldest are dropped and the status says how many. When lines are dropped at the cap, the next line written carries `gap: n` (G210's format text), so the file says it is not whole;
   - the queue's key is per install: in `LEFT_OUT` (a test on the backup keys), so its pending lines are never restored on another device and written under that device's name.
2. **The module:** `app/src/sync/queue.ts`, its port (`appendChecked`, the kv) injected, an `onStatus` callback.
**Done when:** the tests pass; `npm run size` passes with the start chunk unchanged. Placement: `app/src/sync/`, lazy. For shared files: docs/04 6.2's table gains the queue's key, under what a backup leaves out (`backup.test.ts` pins the stored keys to that table).
