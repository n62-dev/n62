### gorge, G318: an engine that cannot start stops after two tries and says so, branch `p1/gorge-startcap`
**Lane:** B, night-safe, Opus (the engine client). **Starts when:** –. Before the tag.
**Why:** (arch review 2026-11-10, second pass; probe `restart-loop.ts`, in the report) A worker that fails at every start is started again without limit, and `ready()` never settles, so the screen stays on "Starting the engine…". With a fake worker that answers every `init` with `fatal` and `dead: "memory"`, or fires `onerror`, `WorkerEngine` spawned 96 workers in 500 ms and `ready()` stayed pending. A plain load error (no `dead`) spawns one and rejects, as it should.
- Cause: `app/src/engine/workerEngine.ts:306-314` (`restartAfterCrash` always calls `start()`); `:326-333` (a `fatal` reply marked dead restarts) and `:337-339` (`onerror` restarts); `:220-229` (`ready()` waits for the start that replaced the failed one). G19's limit (`MAX_FAILED_STARTS`, `:48`, `:311`) holds only for a stored log (`this.log.length`).
- Reach: a browser where the wasm cannot get its memory (`MAXIMUM_MEMORY=1GB`, `engine/giac/build-wasm.sh:245`; iOS Safari not verified), a worker script that does not load (a stale `index.html` after a deploy, with no service worker yet), a browser without module workers.
