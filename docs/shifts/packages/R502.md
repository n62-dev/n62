### ron, R502: a Solve Num row takes a unit: the units key on its line, kept with the values, drawn on the row, branch `p1/ron-solverowunit`
**Lane:** A, night-safe, Sonnet (an entry and a stored field; no solve yet, R521 does that). **Starts when:** G500 merged, and R367 and R368 merged (they rewrite the same Num line and the stored record, so the line's grammar is written once); after the v0.1.0 tag (0.2). S45's rsu-2, first half.

**Why:**
- **S45's entry** ([the note](../../research/r-solveunits.md) section 6, decided 2026-11-15): "each row is `X = 3 m`. On a row's line, the number then the units key opens the unit view with one slot after it: that row's unit (≤ 4 presses for a unit at the median, docs/04 4.4)."
- **Today the key is dead in every app:** `openUnits` returns `c.dead()` when `c.shell.app !== null` (`app/src/units/open.ts:67`), and `spec/keyboard.yaml:30-31` says "an app dims the key".
- **A Num row is a plain number:** `enter` takes the line through `plainNumber` (`app/src/apps/solve/app.svelte.ts:161`; R367 widens it to an expression). The stored record has no unit (`Stored`, `:40-51`).
- **The meeting points:**
  - R367 lets a known's line hold an expression, Ans or a stored name, and stores its exact text and facts. Here the row's unit is **one slot for the whole value** (the line's value × the slot), so R367's grammar is untouched.
  - R368 writes a `solve` history row with the knowns and answers. R521, not this package, adds their units to it.
