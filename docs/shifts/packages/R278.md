### ron, R278: the Copy and Paste keys leave the keypad, branch `p1/ron-noclipkeys`
**Lane:** A, Sonnet, no device. **Starts when:** after R276 and R279.
**Why:** (owner, 2026-11-10, point 2, A and B) copying is the hold on a row (R276) and reuse inside N62 is a tap on a row or Store (S53), so the Copy and Paste keys (`spec/keyboard.yaml:110-115`) compete with both. The keys moving is the owner's explicit decision (docs/rules-core.md: keys never move; decisions.md, 2026-11-10). Without them ☰ is the only way to paste from another app, and the status line's ☰ is the hardest place for a thumb, so ☰ gets a key (the G2 has Menu as a key in this column). From the v0.1.0 tag on nothing that works moves, so these cells are final (docs/06 section 3b).
**Read:** (line numbers as of c583492b; recheck at start) `spec/keyboard.yaml:78-115`; `app/src/clipboard/actions.svelte.ts` (the Copy and Paste specials); `app/src/keyboard/route.ts` (the `menu` special), `keyNames.ts`, `opens.ts`, `keyboard.test.ts`; `app/src/i18n/enKeyNames.ts`; `tests/core/core.yaml:425-450` (c437, c445); docs/04 2.6, 5.1; docs/05 3.3, 3.7; docs/06 sections 1 to 3b.
**The cells (owner, 2026-11-10 and 2026-11-12), each with a new stable id:**
- r0c4, id `menu`: the tap is ☰ (`special: menu`, the Menu key). It does what the status line's ☰ does in every view: it opens the view's menu and closes the menu it opened. Where `toggleMenu` reports no menu the press is a dead one (`route.ts`); no view does so today (R83, R145). With another sheet open it only closes that sheet, as every key of the cluster does (docs/05 3.1). Shift stays Settings. The id `help` does not stay on this key: TalkBack's name and the press counts hang on an id, so an id is never reused for another function.
- r2c4, id `select`: Select (`special: selectGrow`, R279). Shift: Help, its legend drawn, dead and dimmed until R197 builds it.
- r2c5, id `deselect`: Deselect (`special: selectShrink`). Shift: **reserved**.
- All three are `source: assumed`: none is the G2's function in its G2 cell.

**A reserved cell:** the spec gives the key no action and no legend in that layer, and the key is drawn dimmed in that layer only. A press there gives the dead key's double pulse, no key pop and ✕ in the flick bubble, and is counted under its id and layer (`deselect:shift`; a flick up is `deselect:up`). It is never a user slot (those stay U1 to U6) and is filled later only with the owner's yes.
