### gorge, G619: Giac's sum of a rational function: the temporary name is always freed, and a failed series route hands over to the antidifference, branch `p1/gorge-sumabps`
**Lane:** B, night-safe, Opus (a Giac patch: memory damage that erases stored names, a crash, hangs, wrong values). **Starts when:** G618 merged (its check then refuses what this leaves). Before the tag if room; else the first after it.
**Why:** (T6b bug hunt 2026-11-16, F432 and F433; probes `../drafts/2026-11-16-ultra/t6b/probes/ratsum.sh`, `ratsum2.sh`, `ratsum3.sh` (+ `.out`), engine `_out/gsl`, phase-1 `418f125e`.)
- **Erased names (F433):** raw or CAS, `A:=5`, then `sum(1/(k*(5*k+3)),k,1,inf)`, then `A` → `A` (the 5 is gone; CAS `A+1` → `A+1`). `VARS()` lists garbage names after it: `[A,k,,pasdeg]`, `[A,��,pasdeg]`, `[A,h��,k,pasdeg]`, `[A,إD,pasdeg]`. 9 of the 35 sweep sums Σ_{k≥1} 1/(k(ak+b)) leave garbage in the list; 5 of them lose A (a=5: b=1,3,6,7; a=6, b=1). - **A crash:** `sum(1/(k*(5*k+4)),k,1,inf)` → `RangeError: Maximum call stack size exceeded` in the wasm (raw; the CAS host throws).
- **Hangs:** `sum(1/(k*(3*k+4)),k,1,inf)`, `(3*k+5)`, `(3*k+7)`: more than 20 s raw (Home stops at its clock; CAS waits its own).
- **Raw errors:** `sum(1/(k*(3*k+1)),k,1,inf)` and `(6*k+2)` → `GIAC_ERROR: Unable to divide, perhaps due to rounding error%%%{12,[2]%%%}+%%%{%%{[-8,0]:[1,0,-3]%%},[1]%%%}…` shown as the result; right 3 − π/(2√3) − (3/2) ln 3 = 0.445181884881.
- **Wrong values:** G618's lists: Σ 1/((k+p)(k+p+d)) is `infinity` for a gap d = 3 and off by 1/d² for d = 4, 5 (right for d = 1, 2); Σ 1/(k(4k+1)) = 2 − 3 ln 2.
- **The right route is in Giac already:** Σ to n then the limit, `limit(sum(1/(k*(a*k+b)),k,1,n),n,inf)`, gives the right closed form for all 35 (checked against (ψ(1+b/a)+γ)/b at 30 digits), and so does the user's own split `sum(1/k-1/(k+3),k,1,inf)` = 11/6 (sumab gives up on it, intg.cc then takes the antidifference).
- **Cause (stock giac 2.1.0, `../drafts/2026-11-11-parisse/archive/base/giac-2.1.0/src/intgab.cc`; our patches do not touch the file; recheck in the pinned tarball):**
  - `sumab_ps` (about 1547-1720) makes a stack identifier `identificateur idx(" sumw")` and gives it an assumption (`assume_t_in_ab(gx,0,1,…)`, about 1570), which enters Giac's global name map. It is purged (`purgenoassume`) only before a `return true` or an `undef`; every `return false` (sumab_int failed, `remains` non-zero in the r = 0 branch, the end of the function) leaves the entry, whose name dies with the stack frame. The comment at about 1566-1568 warns of exactly this ("the global map is not sorted correctly anymore").
  - `in_sumab_int` (about 1500-1534): the fractional-shift branch gives up when the value at 0 is infinite (`if (is_inf(tmp1)) return false;`, "for sum(1/((n+1)*(2*n-1)),n,0,inf)"); the integer-shift branch (about 1522-1527) has no such test, so `tmp1-limit(tmp1,gx,0)` turns into ∞ and the sum into `infinity` (Σ 1/(k(k+3))). `in_sumab` (about 1732-1750) tries the partial fractions first; ∞ − ∞ is undef there, so it retries the whole summand, which reaches this branch.
