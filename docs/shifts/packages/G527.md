### gorge, G527: rule C: a polynomial equation shows as many real solutions as it has, or none, branch `p1/gorge-rootcount`
**Lane:** B, night-safe, Sonnet (one new refusal, one Giac call; oracle cases decide). **Starts when:** G405 merged (it fixes the cause in patch 0050 and adds the golden rows of the one red input known; this is the net behind it); after the v0.1.0 tag (0.2). G513 later moves the rule into its list.

**Why:**
- **HUNT-2's rule C** (arch review 2026-11-10, `docs/archive/arch-review-2026-11-10/HUNT-2.md:100`): for a polynomial equation with rational coefficients, the number of real solutions shown must equal `nops(realroot(p))`, Giac's exact count of distinct real roots; if it does not, refuse, never show the shorter list. The research note placed it in the shared rule list (`docs/research/arch-review-2026-11-10.md:115`); no package has it.
- **It was red at `5a583f31`** (raw Giac, `smoke.mjs`):
  - `solve(x^3-3*x+2-10^-30=0,x)` → `list[-2.0,1.0]`; `nops(realroot(x^3-3*x+2-10^-30))` → **3**;
  - `solve(x^5-5*x+4-10^-30=0,x)` → `list[-1.65062919144,1.0]`; `nops(realroot(…))` → **3**;
  - Home and CAS show the two-element list with ⚠ (`unaudited: ["solve"]`). Right: three real roots each (mpmath `polyroots`, `source: oracle`: −2, 1 ∓ 5.77E-16; −1.65062919144, 1 ∓ 3.16E-16).
  - G405 fixes these at the cause; `size(solve(…))` = 2 with `=` is G405's (b), not this rule's (a solve inside another call is not checked).
- **`realroot` counts are right where checked:** 1 for `x^3-x-1`, 2 for `(x-1)*(x^3-x-1)`, 4 for `x^4-10*x^2+1`, 0 for `x^2+x+1`, 3 for the cubic above (smoke); HUNT-2 found the same at Digits 12 and 60 on seven polynomials.
