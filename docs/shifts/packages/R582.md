### ron, R582: a physical Escape clears the line and leaves the field typing maths, not in MathLive's LaTeX mode, branch `p1/ron-escmathmode`
**Lane:** A, night-safe, Sonnet (one key listener; e2e with a hardware key). **Starts when:** any time; before the tag if a lane has room (every desktop or Bluetooth keyboard user meets it on the first Esc).

**Why** (F362, found by T4 on 2026-11-16, not the owner; sessions S07 "Android back from every sheet", S13, and the Desktop keys page of Help): after one press of a physical Escape key, the line takes nothing typed, on screen or on the keyboard. Playwright (Pixel 7, real engine, phase-1 e93dec77), `window.n62.entry.field.mode` read after each step:

| Steps | Field mode | Line (`entry.value`) |
|---|---|---|
| fresh Home | math | "" |
| physical Escape | **latex** | "" |
| tap 7 + 1 on the keypad | latex | "" (the 7 shows in blue, MathLive's LaTeX buffer) |
| physical Escape again | math | "" (the buffer is thrown away) |
| desktop: type `2+3`, Escape (Esc = clear, as Help's Desktop keys say), type `4` | latex | "" — the 4 is lost |

It also bit T4's session: assigning U1 through Find, then closing with Escape, left every key "dead" until a reload (the on-screen Esc key does not do it).

**Cause:** the field's Escape handler is a bubbling `keydown` listener on the host (`app/src/entry/field.ts:149-156`, `ev.preventDefault(); on.escape(…)`). MathLive's own keydown handler runs first, at its keyboard sink inside the shadow root, and its default keybinding for Escape in math mode switches to LaTeX mode; the host's `preventDefault` comes too late. The paste handler beside it already uses a capture listener for the same reason (`field.ts:137-148`, R114).

**Read:** `app/src/entry/field.ts:100-160`; `app/src/entry/hwkeys.ts:90-100` (Escape → the Esc key); `app/src/entry/controller.ts:110-120` (`escape` → `onKey("esc")`); MathLive's keybindings (`mf.keybindings`, public API); the specs that press Escape with a sheet open (`tappick.spec.ts:225`, `unitpad.spec.ts:134-169`, `settings.spec.ts`).

1. **Tests first, failing on phase-1** (e2e, `page.keyboard.press`):
   - fresh Home, Escape, then tap 7 + 1 Enter: a row = 8, and `field.mode` is `math` after the Escape;
   - desktop flow: type `2+3`, Escape, type `4`, Enter: the line was cleared by the Escape and the row is = 4;
   - in CAS the same (observed: `mode` is `latex` after Escape there too); Function's Symb line one case.
   - **Controls** (pass before and after): a physical Enter (`2+3` Enter = 5, mode stays math: not affected today); Escape with a sheet open closes it (the specs above); the on-screen Esc key; Escape on a picked row; the unit view's Escape (`unitpad.spec.ts`); the core list.
2. **The change:** handle Escape in a capture-phase listener on the host, as paste is, with `stopPropagation` so MathLive never sees it; or drop MathLive's Escape keybinding from `mf.keybindings` at setup. One of the two, the author picks after the red test; the other path stays a control.
3. **Docs (same diff):** none.

**Done when:** the tests pass and the Escape cases failed on phase-1; the core list passes.
