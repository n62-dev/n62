### gorge, G523: the worst case through a chain: a result chip carries its range, and the next formula uses it, branch `p1/gorge-worstchain`
**Lane:** B, night-safe, Opus (a stored chip field read back into a range: a wrong or stale range is a silent wrong limit). **Starts when:** G518 and R519 merged; after the v0.1.0 tag (0.3).

**Why:**
- **The owner's words are "a ± chain"** (night review 2026-11-09, fh-3, `docs/archive/night-review-2026-11-09.md:73`). G518 refuses a result chip, since a chip holds σ only: `quantityChip` copies the value and `unc` (`app/src/units/chip.ts:13-31`; the `Chip` fields, `app/src/input/chips.ts:12-40`). Using value ± σ as its range would mix a standard uncertainty into a limit, and miss the first step's real worst case.
- **The rule that makes a chain exact:** a result's [lo, hi] from G518 is its true range when its own formula met G518's conditions. The next formula takes the chip as an input with that range. So the chain's range is exact if every step's is and each chip is used once per formula (Moore: a single-use expression of monotone operations), which G518 already counts.
