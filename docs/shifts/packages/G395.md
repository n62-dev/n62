### gorge, G395: the library keeps the registry's names, and Copy as Python names them, branch `p1/gorge-namefiles`
**Lane:** either, night-safe, Sonnet (formats, after G394's design). **Starts when:** G394 merged; after the v0.1.0 tag (0.2), before R346.

**Why:**
- **Library files hold Giac text with engine names** ([the design note](../../research/name-rules.md) section 4). A ΔT exported today would come back as a plain `DeltaT`. Worse, a file's plain `DeltaT` imported where ΔT holds `DeltaT` would silently read ΔT's variable.
- **The format is kept for good** (`docs/release-0.1.0.md` point 7), so the change must be additive.
  - **Today's reader:** a comment line followed by a blank line is nothing. A comment is a description only on the line just above a definition (`app/src/engine/library.ts:144-164`, `:202`).
  - **The stamp is `DATA_VERSION`:** an older reader refuses a newer stamp (`library.ts:133-135`). So v0.1.0 refuses a file written after G394, as with any step, and reads none of the new lines.
- **Copy as Python** writes engine names (`clipboard/python.ts:625`). `DeltaT = 5` is right, but it does not say "ΔT".

1. **Tests first, failing on phase-1:**
   - **vitest, `engine/library.test.ts`:**
     - **Export:** with the pair ΔT↔`DeltaT`, the file has `// name ΔT DeltaT` after the stamp, then a blank line. A file with only plain names has no block.
     - **Import into an empty registry:** the pair is registered, and Vars shows ΔT.
     - **A clash:** a file whose block says ΔT is `DeltaT` while here `DeltaT` is a plain name, or ΔT is `DeltaT_`, is refused naming both names, with nothing defined.
     - **A plain clash:** a file defining a plain `DeltaT` (no block) where `DeltaT` is ΔT's is refused the same way, never aliased.
     - **A block line outside the grammar** (`// name 2x x2`) is refused at its line.
     - **Controls:** every file in `tools/probes/library/` gives today's result, and a v0.1.0 file (old stamp, no block) imports with plain names.
   - **`tools/probes/library/greek.txt`** (a new good file, with a block): `node tools/probes/library.ts check` passes, and the export of its import is byte for byte the same file.
   - **vitest, `clipboard/python.test.ts`:**
     - a row `5▶\operatorname{\Delta T}` gives `DeltaT = 5  # ΔT`;
     - a plain `rate` gives `rate = …` with no comment;
     - a pair whose engine name is `DeltaT_` gives `DeltaT_ = 5  # ΔT`.
   - **The round trip, e2e:** define ΔT, store, export the library, Clear all, import: Vars shows ΔT = 5, and Copy as Python of its row has `# ΔT`.
2. **The change:**
   - **`library.ts`:**
     - reads the block (lines `// name <display> <engine>` right after the stamp, up to the first blank line) only in a file whose stamp is G394's version or later; in an older file such a line stays a comment or a description (test: a v0.1.0-stamped file whose first definition has the description `// name of the beam` imports as today);
     - checks each pair and each defined name against the registry before anything is defined;
     - writes the block on export.
   - **`aiFormat.md`, one rule:** "a name with a Greek letter: list it in the `// name` block; its engine name is its spelling (ΔT is `DeltaT`)".
   - **`python.ts`:** the comment when the display differs.
