**Why** (sandra, 2026-11-28; `../drafts/2026-11-28-owner-bugs5/bksp-model.md`, probes `hunt.jsonl`, `model.jsonl`, outside the repo):
- ⌫ right after a structure only steps into it (point 5: `stepIn`, `delete.ts:130`; `toExponent`, `:333`; deleteAtBoxes, `:393-407`). That press only moves.
- The hunt's dead presses: A1 has 4 of 10, D2 5 of 11, B1–B5 2 of 6, and M1 `2 x² ⌫` takes 3 presses to get back to 2.
- The power path tells "the key's own" exponent by its value, 2 or −1 (`delete.ts:228`). Typed `xʸ −1` (M20) gives the same `2^{-1}`, so the rule cannot hold.
- What no path takes falls through to MathLive's own delete (`:76-77`, `:389`), whose ⌫ leaves half pairs and invisible boxes (probe N4, N5, N8).

**The result: rule 2, and every press is ours.**
- Right after a node, ⌫ acts at the end of its last box in the same press: it deletes the last leaf inside, and the cursor goes where that leaf was (rule 1, or rule 3 if the box is empty). When that leaves an extra box without a value (□ or a lone sign) and the node is then bare, the node goes too and its main content stays. A main box shows □.
- Inside a box (rule 1), ⌫ deletes the one leaf before the cursor; a box it empties shows □, selected.
- Del is the mirror: before a node, it acts at the start of the first box. A box with no left edge is the line's.
- Every leaf is deleted as a one-atom range (as `inLogBase`, `:100-109`, does now), so MathLive's own `onDelete` is no longer reached for the entry line.
