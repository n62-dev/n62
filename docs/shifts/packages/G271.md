### gorge, G271: σ's terms leave the worker, each naming its input, branch `p1/gorge-uncterms`
**Lane:** night, Opus (`pasuu` is the propagation everything else rests on). **Starts when:** v0.5 work opens.
**Why:** `pasuu` computes each input's term and throws it away (`app/src/units/evaluate.ts:108-114`: `h:=diff(g,v[k]); d:=subst(h,w); s1:=s1+d^2*u[k]^2`, the return holds only σ, the second-order share and the flag). The uncertainty budget needs those terms and needs to know which input each came from; `UncVar` has only `{name, value, sigma}` (`app/src/units/types.ts:90-94`), though the builder already holds the key (`uncVar(key, …)`, `app/src/units/build.ts:132-140`: a constant's id or `pasl_<leaf>`; `uncertainValues`, `:184-191`: a chip's `pasr_<n>`, none for a typed ±). Terms are decimals, not engine text: `parseDecimal` rejects `16/625` and `cos(12/5)`, and a term carries the dimension symbols until they are set to 1 (only `pasuo` does that today, `evaluate.ts:87`).
**Read:** (line numbers as of de659c02; recheck at start) `evaluate.ts:44-114`, `:291-332` (`uncertainty`); `types.ts:89-94`, `:145-156`; `build.ts:131-196`; `app/src/engine/constBasis.ts`; decisions G18, G41, G81, R61, R115; GUM 5.1.2 note.

2. **The change.**

   - `pasuu`: a fourth element, the list of `[evalf(subst(d^2*u[k]^2,S,ONES),30), evalf(abs(subst(d*u[k],S,ONES)),30)]` per input and `evalf(subst(s2,S,ONES),30)`, built from the `d` it already has, with no second `diff`. The order of `[σ, share, flag]` stays, so `parts[0..2]` read as before.
