### ron, R250: the RPN stack model, UI-free, branch `p1/ron-rpnstack`
**Lane:** A, day, Opus (a new entry model). **Starts when:** section C's order is done (the v1 slot, `docs/must-have.md` section D) and the owner's yes on mh-D1 (recommended: yes, Home only, a third Entry value).
**Why:** (mh-D1) entry today is `"textbook" | "line"` (`app/src/state/session.svelte.ts:42`), with no RPN code; Giac's own RPN is compiled in but unreachable and must stay so (`app/src/engine/flags.ts:143`), because it bypasses exact-first, the marks and the chips. So the stack holds **result chips** (`Chip`, `app/src/input/chips.ts:24`, docs/04 2.8) and nothing new evaluates.
- **One chip used twice is one input** (decisions.md R61, `app/src/input/parse.ts:548-556`): `dup` must keep the same `res:k`, so `x dup ×` stays correlated. The wrong σ arises **across rows**: in `x dup × x ×` the x² chip is a new independent input. So a chip with `unit` or `unc` is refused on the stack; Home has no units either (`chips.ts:9`, P8).
- A result with no chip (`chipFor` undefined: a non-number over 2 kB, `session.svelte.ts:459`; an exact number over 2 kB has a confirmed-decimal chip, docs/04 2.8) cannot be pushed.

**Arity (the table R251 reads, by key id and layer in `spec/keyboard.yaml`):**

| Arity | Keys |
|---|---|
| 2 (level 2 op level 1) | `add`, `sub`, `mul`, `div`, `pow`, primary |
| 1 (level 1) | `sq` primary (x²), `sq` shift (√), `div` shift (x⁻¹), `sin` `cos` `tan` `ln` `log` primary and shift, `neg` shift (abs), `enter` shift (approx) |
| 0 (no stack effect) | `emark` (both layers), `paren`, `d8` shift (list), `frac`, `pow` shift (nth root), the palettes, every other key |

`ANS_FIRST` (`app/src/entry/ans.ts:7-15`) is not this table: it mixes binary keys with `sq`, x⁻¹ (unary) and Store ▶.
