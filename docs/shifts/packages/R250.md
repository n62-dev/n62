**Why:** (mh-D1) entry today is `"textbook" | "line"` (`app/src/state/session.svelte.ts:44`), with no RPN code; Giac's own RPN is compiled in but unreachable and must stay so (`app/src/engine/flags.ts:143`), because it bypasses exact-first, the marks and the chips. So the stack holds **result chips** (`Chip`, `app/src/input/chips.ts:24`, docs/04 2.8) and nothing new evaluates.
- **Units and ± stay on a level** (mh-D3, the owner, 2026-11-15): a chip with `unit` or `unc` is pushed like any other. One chip used twice is one input (decisions.md R61, `app/src/input/parse.ts:590-600`; the unit view keys it `pasr_<k>`, R115). A level's identity is its row's **uid** (G211, `rowUid`, `app/src/state/results.ts:21`), which survives a relaunch. A unit-view row replaced within one visit keeps its uid while its value changes (`app/src/state/resultItem.ts:127`), so two levels are one identity only when uid and chip (value, `unc`, unit text) are equal. Neither a row id (of one run, `session.svelte.ts:788`) nor a line's `res:<k>` (the entry's own counter, `app/src/entry/controller.ts:40, 218`) names an input. `dup` copies the uid, so `x dup ×` stays correlated. Across rows a result is a new independent chip, so in `x dup × x ×` the x² level and x would count x twice. Each level keeps `inputs`, the σ inputs it rests on, and two levels with different uids whose `inputs` meet are never combined (`sharesInput`; R251 refuses), so within the stack no σ counts an input twice.
- A result with no chip (`chipFor` undefined, `session.svelte.ts:511`: a non-number over 2 kB; an exact number over 2 kB has a confirmed-decimal chip, docs/04 2.8) cannot be pushed.

**`inputs`** (sorted, no repeats): a level pushed from a row with σ holds `row:<uid>` of that row, plus `const:<ID>` for each σ constant chip on its line (with a basis, G81: `pasl_<leaf>` for each leaf, as G271 keys them). The line's `res:<k>` keys are never used. A σ result chip on that line (and, after G371, a σ stored name) names no source row, so it counts as a new input, as on the algebraic line (R61); the report says so. An operation's level holds the union of its operands' inputs. A level with no σ holds none.
