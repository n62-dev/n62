### gorge, G276: a set's step is evaluated as one closed expression over the inputs, branch `p1/gorge-setclosed`
**Lane:** night, Opus. **Starts when:** G275 and G271 merged.
**Why:** a step built on an earlier step must not reuse the earlier result as a chip. R61 makes a chip an independent input, and if two operands of one step share an input, that correlation is ignored and σ is wrong in either direction (mpmath, L = 2, u = 0.01): M = L² chained into M·L gives 0.0894 where the truth is 0.12, and M/L gives 0.0224 where the truth is 0.01. `σ = M/W` is wrong only if W or another operand shares an input with M. The units path already does what is needed: `pasupm(v,s,pasr_<n>)` with one key is one input (`app/src/units/build.ts:184-191`), and a slot placeholder may repeat (`:472-479`), so the fix is a formula, with no change to the builder.
**Limits, from `build.ts`:** keys must pass `isChipName` (`app/src/engine/ourNames.ts:58`: `pasr_` and digits), so an input's key is `pasr_<its index>`. An input in °C, °F or a level is refused unless alone in the formula (`build.ts:428-434`).
