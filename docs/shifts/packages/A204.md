**Lane:** B, night-safe for the web part, Sonnet; its last step is the night's device step (the core list in the Android WebView). **Starts when:** after the v0.1.0 tag (0.3).

**Why:** (arch review 2026-11-10, B4, draft X21; rechecked at `5a583f31`)
- **No policy exists:** no `Content-Security-Policy` in `app/index.html`, `app/vite.config.ts`, `app/vite-plugin-pwa-lite.ts`, `app/capacitor.config.ts` or `app/pwa/` (grep).
- **The page injects markup built from stored text:** `{@html markups[i]}` (`app/src/render/Math.svelte:36`) draws what MathLive builds from LaTeX that the user's store, a backup file or another device's synced file holds.
- **The promise "nothing is sent" is held only by our code.** Today every `fetch` is same-origin (`app/src/find/finder.ts:75`, `app/pwa/sw.js:37`, `:73`); on the web build only a policy makes the browser hold it.
- **What a policy must allow:** two inline scripts in `index.html` (`:13`, the stored look before first paint; `:41`, the browser check), the first writing a stylesheet link with `document.write` (`:32`); a module worker that `import()`s the engine (`app/src/engine/giac.worker.ts:19`) and compiles wasm; JSXGraph on a canvas; MathLive and Svelte writing style attributes; the Report a problem link (`app/src/clipboard/report.ts`), a navigation, not a `connect`.
- **(to verify, step 1):** Capacitor 8's Android bridge is injected into the served page as an inline script (its `JSInjector`); a hash-only `script-src` may block it in the APK. The web build is the one the promise needs most.

   - the built page carries a policy (`meta[http-equiv=Content-Security-Policy]`);

2. **The change:**
   - a small Vite plugin (`transformIndexHtml`, `order: "post"`, so the hashes are of the final inline scripts) writes `<meta http-equiv="Content-Security-Policy">` as the first element of `<head>` after `charset` (a meta policy covers only what comes after it) at build time: `default-src 'self'`; `script-src 'self' 'wasm-unsafe-eval'` plus the SHA-256 of each inline script (computed by the plugin); `style-src 'self' 'unsafe-inline'`; `img-src 'self' data: blob:`; `worker-src 'self' blob:`; `connect-src 'self'`; `object-src 'none'`; `base-uri 'self'`. The dev server gets none. A meta policy covers the page, not the engine worker (a worker takes its policy from its own response headers, which neither the static host nor Capacitor sets): the report says so, and the test checks the page only.
   - if `document.write` of the stylesheet link is blocked, the inline script creates the link with DOM calls (its hash follows).
   - **step 1 on the device:** the APK with the policy, the core list on the night's device. If Capacitor's bridge is blocked, the APK build leaves the policy out (one flag in the plugin, the reason in the report) and the web build keeps it.
3. **Docs (the same diff):** docs/04 section 8's web build line: "a Content-Security-Policy: same origin only" (one clause, replace in place); `docs/release.md` if the APK has no policy, one line why.
