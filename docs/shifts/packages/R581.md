### ron, R581: Paste reads a grouped number from outside (1,234.5 and 12’345.6) when it cannot mean anything else, branch `p1/ron-pastegroups`
**Lane:** A, night-safe, Sonnet (one reader function, unit tests). **Starts when:** after the tag (the owner's yes, 2026-11-16).

**Why** (F361, found by T4 on 2026-11-16, not the owner; session S18 "paste from outside (3.14, 2E3, 1,234.5)", "Want: no digit lost"): Playwright (Pixel 7, phase-1 e93dec77, decimal point setting), ☰ 7 Paste:

| Clipboard | Now | Wanted |
|---|---|---|
| `3.14`, `2E3`, `1.5e-3`, `−5`, `6.02214076×10^23` | the number | (unchanged) |
| `1,234.5` (a spreadsheet, a datasheet) | "Paste: not a number" | 1234.5 |
| `12'345.6`, `12’345.6` (Swiss; N62's own ’ digit groups, R125) | "Paste: not a number" | 12345.6 |
| `1 234 567.89`, `1 234.5` (thin, no-break or plain spaces, as N62 draws groups) | refused | 1234567.89, 1234.5 |
| `1,234` (point setting, no point) | refused | refused (could be 1.234 in a comma country) |
| `1 234,5` (point setting) | refused | refused |

Every number N62 itself copies pastes back already (Copy and Copy as › As shown drop the groups: `1234567.89`, `3.33333333333E19`, `1.41421356237*i`, all read back; P5 holds). The gap is text from elsewhere.

**Cause:** the reader takes digits, one decimal mark and an exponent only (`realPattern`, `app/src/clipboard/paste.ts:22-27`; docs/04 2.6 "Paste": "one number (`-1.5`, `1,5` with decimal comma, …)").

**The rule (unambiguous only):** strip group marks — `,` (point setting only), `'`, `’`, a space, a thin or no-break space — when every group after the first has exactly three digits and the number then has the setting's decimal mark (or an exponent). A grouped integer with no decimal mark is refused when its group mark could be the other setting's decimal mark (`1,234` with the point setting; `1.234` with the comma setting); `12’345` (an apostrophe is never a decimal mark) is read.

**Read:** `app/src/clipboard/paste.ts`; `app/src/clipboard/actions.test.ts:80-90` (the refusal case); the decimal-comma setting (`decimalMark`); docs/04 2.6.

1. **Tests first, failing on phase-1** (vitest on `paste.ts`, both settings): the "Wanted" column, row by row, plus `1,234,567.891` → 1234567.891 and `12’345’678` → 12345678. **Controls:** every existing paste case (lists `{1,16}`, `{1,5;2,25}`, the unit row text, complex, `1,5` with the comma setting); `1,23.4` (a group of two) refused; `1,234` with the point setting refused.
2. **The change:** a `degroup` step before `realPattern`, applying the rule above; nothing else moves.
3. **Docs (same diff):** docs/04 2.6's Paste sentence names grouped numbers (in place, budget).

**Done when:** the tests pass and the grouped cases failed on phase-1.
