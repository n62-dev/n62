### annabell, A271: at Home or CAS with nothing open, back twice to leave, branch `p1/annabell-backtwice`

Broken (daily reach). **The owner (2026-11-23, bug list 4 point 7):** with nothing open, the first back shows "Press back again to leave"; a second back within 2 s leaves. CAS is a root like Home (no stop at Home first). **Found by:** sandra b4b, sofia (design corrected); `../drafts/2026-11-23-owner-bugs4/b-report.md`, verify.md.
**Why:** today one back at Home or CAS with nothing open leaves N62 at once; a back meant to close something that was already closed takes the user out.
**Cause:** `android/app/src/main/java/.../MainActivity.java:50-66` (`installBack`): an always-enabled `OnBackPressedCallback`; when `webView.canGoBack()` is false (`:55`) it re-dispatches and the activity finishes.
**The design (sofia):** the page holds the 2 s window, so a notice is never skipped. At the root Java asks the page with `evaluateJavascript("window.n62RootBack?.()")`: the page answers `"stay"` (it showed the notice and opened its 2 s window) or `"leave"` (a second back inside the window); no answer or an error leaves as today. The window resets when a layer opens or closes and when the app goes to the background (`visibilitychange`). The handler lives in a lazy chunk (the clipboard chunk, `clipboard/actions.svelte.ts`, idle-loaded at `App.svelte:140`); until it loads, back leaves as today. The notice is the existing one (`this.say(t("back.again"), 2000, true)`, `App.svelte:494`, `role="status"`, read by TalkBack). No start-chunk bytes (~15 B left at the pin; the report gives `npm run size`'s line).
