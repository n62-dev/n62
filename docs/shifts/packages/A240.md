### annabell, A240: the UI walk becomes a test: every edge of the map on the night's device, once a week, red on a change, branch `p1/annabell-uiwalk`
**Lane:** B, Sonnet; the night's device (the test build). **Starts when:** R700, R701 and R709 merged (so the first committed map has no known failure in it); after the v0.1.0 tag. It is tooling. It joins the weekly extreme night (brief section 0), so no night gets longer.

**Why:**
- **T5 built `app/test-device/uiwalk.ts`.** It maps every state and edge of the UI over adb (sheets, layers, overlays, Back, ×, flicks, holds, swipes) and checks each edge:
  - the state reached;
  - Back and ×;
  - console errors;
  - overflow;
  - 48 dp targets;
  - spoken names;
  - the time from lift to change.
- **What it found** ([findings.md](../../research/t5-ui/findings.md)): F380–F384.
  - Two of these (F380, F381) no other test could see. Each needs the real WebView: Capacitor's plugin proxy, and Android's Back.
  - F383 shows that a desktop emulation can pass while the device fails.
- **The walk catches change:** a later package that moves a sheet's level, breaks Back or adds a control without a name makes a line of its report red.

**Read:** line numbers as of the T5 merge; recheck them at the start.
- `app/test-device/uiwalk.ts`, `uiwalk-page.ts`, `uiwalk-report.ts`, `uiwalk-merge.ts`
- `docs/research/t5-ui/SUMMARY.md` ("How it was made")

- `tools/README.md`

- brief section 0 ("The weekly extreme night")

1. **Tests first:**
   - **`tools/uiwalk-device.test.sh` (pure bash, in the gate):**
     - `tools/uiwalk-device.sh --dry-run` prints the commands it would run: the device lock, stay-awake, `node test-device/uiwalk.ts --mode walk --profile <phone|tablet>` with `ANDROID_SERIAL`, then the report.
     - It refuses without `ANDROID_SERIAL`.
     - It exits 1 when the walk's summary line says fewer edges as mapped than the map holds.
   - **A self-test of the walk, `app/test-device/uiwalk.selftest.ts`, run by the script first:** on the device, three edges of the committed map pass (the place → Apps, ☰ key → Home menu, Back from Apps → Home). One edge with a wrong `to` fails. So a broken walker is not read as a broken app.
2. **The change:**
   - **`tools/uiwalk-device.sh`:** the wrapper; it holds the device's lock, as `core-device.sh` does.
   - **The walk's result:**
     - `UIWALK <profile> <as mapped>/<edges>, back <bad>, names <bad>, targets <new>`, one line, plus `.coord/uiwalk-<date>.json`;
     - a failed edge's screenshot goes to `.coord/` (gitignored, as the device runs' are).
   - **A changed UI on purpose:** the package that changes the UI regenerates the map (`--mode map`, then the merge), and commits `ui-map.json` only. The per-state screenshots stay out of git (`.gitignore`; owner 2026-11-16). The audit reads that diff as the UI change.
   - **The night's place:** in the weekly extreme night, after CORE DEVICE, in 10-minute slices by root (`--roots`): one root per slice.
3. **Docs (the same diff):**
   - `tools/README.md` (the command, the lock);
   - brief section 0 (the weekly night's row);
   - SUMMARY.md's "How it was made" points to the script.

**Done when:** the bash test passes in the gate; a dry run and one real run on the night's device end in the UIWALK line with every edge as mapped; the report quotes the line and the slice times.
