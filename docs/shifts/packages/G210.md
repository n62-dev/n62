### gorge, G210: one result as one JSON line (session format v0), branch `p1/gorge-sessionline`

**Why:** (owner's must-have list, B: "one JSON line per result (input, Giac text, exact, value at full precision, mark, unit, σ, defs used), appended, never edited") Nothing writes it today. `HistoryItem` (`app/src/state/session.svelte.ts:97`) holds `latex`, `value`, `facts`, `full`, `fullExact`, `units`, `chips`; the Giac text, the angle and the digits of a row are not kept, and a row has no identity that outlives a run (G211 adds them). **Read:** docs/04 2.6 and 2.8; `app/src/clipboard/text.ts:95-133` (`copyFull`, `copyMark`); `app/src/state/resultItem.ts`; `app/src/units/row.ts:35-55` (`units`, `unc`, `why`); `app/src/units/types.ts:100-130`; `app/src/input/chips.ts` (`Chip`, `ChipTable`); `app/src/input/chip-giac.ts:15-21` (`chipName`).
1. **Tests first, failing on phase-1** (`app/src/state/sessionLine.test.ts`, fixed rows, no engine): an exact row, a ≈ row, a ⚠ row with its reason, a unit row with σ and `why`, an error row, a chip input, a DEG row. Each row gives one exact line: the expected text is written in the test, key order fixed.
   - The chip input: `\res{7}` in `input`, `pasr_7` in `giac`, and the entry `res:7` with its value in `chips` of the same line.
   - Identity, on fixed rows that carry a `uid` (G211 runs the same cases on a real session): two lines made from one row before and after a store round trip (its `HistoryItem.id` changed) have the same `id`; three rows, the second deleted, a restart and a fourth row give four different ids; a row without a `uid` gives `id: null`.
2. **The function:** `sessionLine(item, { t, app })` in a new `app/src/state/sessionLine.ts`, pure, no runes, type-only import of the session (`app/src/units/row.ts:13-15` says why). Fields, in this order: `v:0, app, id, t, view, input (latex), giac, chips, ok, error, exact, value, mark, warn, reliableDigits, unit, dim, sigma, sigmaWhy, angle, digits, defs`.
   - `v` is 0 until a release says the format is kept; from 1 on it rises only when the meaning of an existing field changes.
   - `app` is the app's version (`0.1.0`): `input` and `giac` are N62's own texts (`\res{7}{…}`, `pasr_7`, `pasdeg`, `e_`) and their reading belongs to that version.
   - `id` is the row's `uid` (G211), never `HistoryItem.id`: that number starts at 1 in every run and every stored row gets a new one at each start (`session.svelte.ts:236`, `:782`). A row without a `uid` gives `id: null`.
   - `t` is when the line was written, UTC, ISO 8601 ending in `Z`.
   - `chips`: for each chip key in the row's table (`res:7`, `const:c`) the value it held and whether it is exact; `\res{k}` in `input` and `pasr_<k>` in `giac` name that entry of the same line, never another line. Absent when the row has no table. A row keeps no entry for Ans (`session.svelte.ts:459-468`): the report says what a line with `\ans` then lacks.
   - `exact` is `full` when `fullExact`, else absent. `value` is `copyFull` with the decimal point, whatever the user's decimal mark. `mark` is `=`, `≈` or `⚠` from `facts` as `copyMark` reads them.
   - `unit`, `dim`, `sigma`, `sigmaWhy` come from `item.units`; absent otherwise.
   - `defs` is `item.uses` (name, preview, view), absent when empty.
   - `giac`, `angle`, `digits` and `uid` are four optional fields added to `HistoryItem` as types only in this package (no bytes; G211 fills them); absent on a row gives `null` in the line (`angle:null`, not a guess).
3. **The format text** in the module header, and as "For shared files" text for docs/04 2.6: one line per result, UTF-8, `\n`. A reader skips a torn last line (a crash can leave one). It ignores a field it does not know and does not rely on the order of fields; any field can be absent or `null`. A repeated `id` that is not `null` (delivery is at least once, G219): the last one wins. `gap: n` on a line says n earlier lines were dropped before it (G219).
