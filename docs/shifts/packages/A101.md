### annabell, A101: a checked append: read the tail, never switch mode, branch `p1/annabell-appendcheck`
**Lane:** day, on the Tab One for the torn-line check, Opus. **Starts when:** A100 merged, and the owner's yes on "no rewrite mode" (recommended: yes; a folder that cannot append says so and keeps the queue).
**Why:** Rewrite mode was the plan's fallback; it is truncate-then-write per result (A65's report, 73c12729), so a crash in the window loses confirmed lines, and it contradicts the owner's "appended, never edited". A size check against a stale `COLUMN_SIZE` on a cloud provider must therefore not switch any mode (risk reasoned, not probed). So: re-read the tail. This is decided in TypeScript on the plugin's primitives, so vitest covers it; only the primitives need a device.
**Read:** `app/src/clipboard/folder.ts`, `folder.test.ts`; `N62FilesPlugin.java` (`read`, `READ_MAX`, A100's `append`).
1. **Tests first, failing on phase-1** (`folder.test.ts`, port stubbed): `appendChecked(name, text)`:
   - sizes `before + bytes == after` → "appended", no tail read.
   - sizes say otherwise, or `-1`, and the file's last bytes equal `text` → "appended".
   - last bytes differ, or `"wa"` throws → "cantAppend"; the caller keeps the line queued.
   - a file not ending in `\n` gets `\n` prepended to `text`, so a torn line stays on a line of its own for the reader to skip (G210's format text).
   - "unavailable" passes through.
2. **The plugin:** `tail({name, n})`: the last n bytes (a seek, else a bounded read), `{result:"ok", text}` | "missing" | "unavailable".
3. **`folder.ts`:** `appendChecked`, the only caller of `folderAppend` from here on.
4. **Device:** torn last line: a file written without its final `\n`, then `appendChecked` twice: the torn line alone on its line, both new lines whole.
**Done when:** the tests pass; the device run passes; no `"wt"` is added and no temp file is written (the audit reads the diff); `npm run size` passes with the start chunk unchanged. Placement: `folder.ts`, lazy.
