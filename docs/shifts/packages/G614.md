### gorge, G614: a sum's index keeps no assumption inside the sum, and a sum leaves the user's assumption as it was, branch `p1/gorge-sumassume`
**Lane:** B, night-safe, Opus (a Giac patch; a wrong value with no mark). **Starts when:** –. Before the tag; before the freeze if room (it needs `assume` on the index first).
**Why:** (T6b bug hunt 2026-11-16, F426 and F429; probes `../drafts/2026-11-16-ultra/t6b/probes/cas.mts`, engine `_out/gsl`, phase-1 `418f125e`.)
- **What happens (F426):** CAS or Home, `assume(k>0)` (or `k>=1`, `k>1`; `assume(n>0)` with n as index), then `sum(1/k^2,k,1,inf)` shows `infinity`, unmarked. Right π²/6 = 1.64493406685 (`source: derived`, Basel). Each after a fresh `assume(k>0)`:
  - `sum(2/k^2,k,1,inf)`, `sum(1/k^4,k,1,inf)`, `sum(1/k^2,k,2,inf)`, `sum(1/k^2,k,-inf,-1)` → `infinity` (right π²/3, π⁴/90, π²/6−1, π²/6)
  - `sum((-1)^k/k^2,k,1,inf)` → `undef` (right −π²/12)
  - Fine under the same assumption: `sum(1/k^3,…)`, `sum(1/(k^2+k),…)`, `sum(1/(k^2+1),k,0,inf)`, `sum(k/3^k,…)`, `sum(1/k!,…)`; with no assumption every one above is right. `assume(k,integer)` is fine.
- **Cause (stock giac 2.1.0, `../drafts/2026-11-11-parisse/archive/base/giac-2.1.0/src/intgab.cc`; recheck in the pinned tarball):**
  - An even rational summand goes through the residue path of `in_sumab` (`is_meromorphic`, about 1952): `vecteur v=singular(g,x,contextptr)` (about 1971), then `res=(-quotesubstcheck(g,x,0,v)-somme_residus)/2` (about 2003).
  - `singular` honours the user's assumption on the index: raw `singular(1/k^2,k)` = `[0]`, after `assume(k>0)` = `[]`. So the pole at 0 is neither summed as a residue nor skipped, and g(0) = 1/0 gives ∞ (undef for the alternating one).
- **What happens (F429, low):** `assume(k>0)`, then `sum(1/k^2,k,1,n)` (a symbolic bound), then `about(k)` → `k`: the sum removed the user's assumption, silently; `sqrt(k^2)` is `abs(k)` afterwards. G92 puts back what Giac's commands leave or remove, but only for the words in `app/src/engine/assumed.ts:18-21` (`ASSUMING_WORDS`), and `sum` is not one.
- **Why N62 misses F426:** `infinity` is a limit value the CAS view keeps (converge.ts:287-292: only Home's integrals turn ∞ into a refusal), and Home's `seriesCheck` sees no finite value to check.
