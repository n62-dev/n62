### gorge, G785: Fmt skips a step that draws what the row already shows; a press that changes nothing is a dead press, branch `p1/gorge-fmtskip`
**Lane:** v0.1.1, Opus. **The owner's yes:** 2026-11-22, his point 23 ("first press does nothing", cycle STD SCI; his digits were 6, so the digits half is right and dropped) and point 24. **Starts when:** at once. A fix (a press that looks dead).
**Why:** sandra's probe (`../drafts/2026-11-22-owner-bugs3/s4-probe-fmt.spec.ts`, `s4-probe-fmt2.spec.ts`, outside the repo), rerun by sofia (verify.md S4) with digits 6 and the cycle STD SCI:
- CAS `5` Enter, then Fmt three times: `5 → 5 → 5.00000E0 → 5`. Press 1 is dead.
- Home with Mode Format PFX: `5 → 5 → 5.00000E0`. Press 1 is dead.
- Default cycle STD SCI ENG at digits 12: `5 → 5.00000000000E0 → 5.00000000000E0 → 5`. Press 2 is dead, because SCI and ENG draw alike when the exponent is a multiple of 3 (1 ≤ |x| < 10, 1000 ≤ |x| < 10 000, …).
- Cause: `nextMode` (`app/src/state/cycleForms.ts:85-96`) steps by place in the list, never by what the step draws. In CAS the exact form is step 0 and STD step 1 (`:93`). In Home a global format that is not ticked gives `indexOf` −1, so the cycle's first step, STD, comes next (`:94`, read at `:134`).
- No dead signal: `Session.formKey` (`app/src/state/session.svelte.ts:663-669`) calls `dead` only when there is no row. The Fmt route passes none (`app/src/keyboard/route.ts:150`). `deadPress` (`route.ts:319`) asks only "is there a row".
- The same holds for a b/c on a whole number (`5`): `nextForm` returns null (`cycleForms.ts:73-78`), so nothing changes and nothing says so (verify.md S4-24).
