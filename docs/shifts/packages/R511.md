### ron, R511: the matrix grid's "2 adds a column" test stops flaking: the keys wait for the menu, the row is polled, branch `p1/ron-matrixflake`
**Lane:** A, night-safe, Sonnet (a test; app code only if the trace shows an app race). **Starts when:** after the v0.1.0 tag (0.2).

**Why:**
- **Backlog "Without a package yet", Flaky (pass 199):** `matrixsize.spec.ts` "2 adds a column of zeros at the end": FLAKE in runs 1228, 1250, 1276 (three in about 50 runs; each a lost pipeline round or a retry).
- **The test** (as of `5a583f31`, `app/test/matrixsize.spec.ts:123-130`): `openM` (store `M`, Shift + 4, row 0, wait for 4 cells), then one `tap(page, ["menu", "down", "enter"])`, then `expect.poll(texts)` and an **unpolled** `expect(await lastLatex(page))`.
- **Why this test flakes and not its neighbours:** it sends two menu keys through `tap` right after the ☰ that opens the menu. Test 1 picks by `sheetKey(page, ["d1"])` (`:113`), the hardware path, which never depends on the screen; test 3 waits on an `aria-label` before its first pick (`:138`) but not before its second (`:143`, then `sheetKey`); the 1 × 1 test sends `tap(page, ["menu", "d1"])` (`:165`), one menu key through `tap`.
- **Two races in that line, both from reading the code:**
  - `tap` decides per key whether the key is under a sheet (`helpers.ts:45-52`, `covered`) and then taps the screen at the key's centre (`:64`). The ☰ press sets `grid.menu = 0` at once (`app/src/views/matrixGrid.svelte.ts:173-176`), but the menu's DOM (`MatrixGrid.svelte:30-36`, sticky at the grid's top) is drawn on Svelte's next flush. Under load the `covered` check of `down` can run before the flush and the tap after it: Playwright's hit check and its dispatch are not one step, so a tap can land on whatever the new menu put at that point, or a key is pressed by the screen when the test meant the sheet.
  - The write-back is `resize` → `commit` → `session.submit` → `await job` → `read(true)` (`matrixGrid.svelte.ts:276-335`); the grid's texts update after the job, and `lastLatex` reads `session.home.at(-1)` once, unpolled.
- The run logs of 1228, 1250 and 1276 are not readable here, so the package reproduces first and names which race it was.
