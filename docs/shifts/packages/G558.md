### gorge, G558: the unit view's "value ± σ" line writes the value the evaluator confirmed, never a fresh 30-digit one, branch `p1/gorge-shownvalue`
**Lane:** B, night-safe, Sonnet (one line's source; pinned by tests). **Starts when:** G556 merged (both edit `units/evaluate.ts`). Before the tag; not a freeze blocker (needs a value that cancels at 30 digits).
**Why:** (T2 bug hunt 2026-11-16, F318; `../drafts/2026-11-16-ultra/t2-bughunt/hunt-sigma.md`, `tools/probes/unit-result.ts`, engine `_out/gsl`, phase-1 `e93dec77`.)
- **What happens:** unit view `(exp(1E-35 ± 1E-36) − 1) m`:
  - The value line says ≈ 1E-35 m and σ 1.0E-36. Both are right: mpmath `expm1(1e-35)` = 1.00000000000000000000000000000000000E-35.
  - But the line the row and Copy show reads "0.0000000000000000000000000000000000000 ± 1.0E-36", and the sheet's short form is "0(10)E-37".
  - `(cos(1E-20 ± 1E-21) − 1) m` fails the same way: −5E-41 shown as 0.000… ± 1.0E-41.
  - The control `1E-35 ± 1E-36 m` shows "1.00E-35 ± 1.0E-36".
- **Cause:** `app/src/units/evaluate.ts:432` evaluates `plain = evalf(valueExpr,30)` again for the shown line. At 30 digits `exp(10^-35)-1` cancels to 0. The value the evaluator already confirmed (`value`, line 431, `numberOf` with the agreement check) is right, and the line does not use it.

**Stored data:** none new. A row stored with the wrong shown text keeps it until it is evaluated again.
