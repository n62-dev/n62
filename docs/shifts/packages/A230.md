### gorge, A230: a probe page that runs the engine in any browser and times start, memory and Cancel, branch `p1/gorge-platformpage`
**Lane:** day, Sonnet; no device (the owner opens the page on his iPhone after the merge, S90). **Starts when:** –; the after-tag lanes (it touches no `app/` file).
**Why:** (t3-research 2026-11-16, iOS and desktop notes) nobody has run the engine on an iPhone, in Safari on a Mac or in WebKitGTK (the Linux webview Tauri would use). A144 ran Linux WebKit in a container, which is not iOS Safari. The riskiest assumption is the Cancel key: rules-core says Cancel terminates the worker. `workerEngine.ts:296-323` terminates the worker and starts a new one at once. WebKit bug 289686 (Safari 18, 2025-03-13) reports that a worker computing in wasm keeps running after `terminate()`. Its fix, 319508@main (commit 03e836de2f7b, 2026-08-20), covers only workers waiting in `Atomics.wait`. A leftover engine computes until Giac's clock stops it: 1.5 s on Home (`homeEval.ts:74`), 600 s in CAS (`engine/types.ts:136`, `host.ts:141`). Start time on a phone without a compiled-code cache is also unmeasured (budget: docs/04 8.3, engine ready < 1.5 s). The Node numbers are in `tools/probes/platform-footprint.ts`: wasm 9.6 MB raw, 2.5 MB brotli, heap 64 MB.
**Read:** recheck at start. `tools/probes/platform-footprint.ts`, `tools/probes/README.md`; `app/src/engine/giac.worker.ts` (how the app loads the engine: module worker, dynamic `import()`, `giac_init`); `app/src/engine/workerEngine.ts:296-330` (stop and restart); `engine/giac/build-wasm.sh:264-268` (exports, memory); A144's report (`git log -1 fa06b2d1`: the WebKit container command).
1. **Tests first, failing on phase-1** (the files do not exist): `tools/probes/platform-page/page.test.mjs` (Node's test runner, Playwright's Chromium from `app/`) serves the page with `serve.mjs`, opens it, presses Run, and waits for the report. It checks the report has every field below and 20 Cancel rounds, and that on Chromium the fixed task's time in the last round is within 3× the first. That last check is the "terminate works" baseline; if it fails on Chromium, the page measures nothing.
2. **The page** (`tools/probes/platform-page/`: `index.html`, `probe.js`, `engine.worker.js`, `serve.mjs`; plain JS, no build, no dependency):
   - `serve.mjs`: Node's `http` on `0.0.0.0:<port>` (5400–5499); serves the page and `giac.mjs`/`giac.wasm` from `GIAC_OUT`, with `application/wasm` and `text/javascript`; prints the LAN address. Nothing is deployed; the phone joins the same Wi-Fi.
   - The report: user agent, `hardwareConcurrency`, `deviceMemory`, `crossOriginIsolated`, `'vibrate' in navigator`. Whether legacy wasm exceptions and exnref validate (`WebAssembly.validate` on two tiny modules). Fetch, compile, instantiate and `giac_init` times. Five everyday inputs (`platform-footprint.ts`'s Home list as raw Giac) with times. The heap (`wasmMemory.buffer.byteLength`).
   - **Cancel rounds** (×20): a worker posts "looping", then runs an endless Giac loop with no clock. After 1 s the page calls `terminate()` and starts a fresh worker. It records the fresh worker's time to ready and its time for one fixed task (`ifactor(2^128+1)`). Leftover engines share the CPU, so a rising fixed-task time means `terminate()` did not stop them. Each round is saved to `localStorage` first. A reload after the tab died says "the tab died in round k" and shows the rounds before it.
   - A Copy button puts the report on the clipboard as text, for the owner to paste into an e-mail or a file.
3. Run it on the host: Chromium and Firefox (Playwright's, as A144), and WebKit in A144's container if it starts. The report shows the three reports.
